# 三款五木储物板条箱

使用用户指定的铁匠家具包 `blacksmith_box_1`、`blacksmith_box_2`、`blacksmith_box_3`，分别命名为盖板款、斜盖款和双层款。五种木材各三款，共十五个新方块，注册名为 `<wood>_storage_crate_1/2/3`。

盖板款和斜盖款为 27 格，双层款为 54 格，与原版大箱子容量相同。原来的 `<wood>_crate` 破坏掉金苹果方块及其行为保留。

## 模型与颜色

- 三份运行时父模型保留原始立方体、旋转、枢轴、UV、零厚度标签和物品展示变换，十五份子模型只选择木材图集。
- 与储物桶使用同一份原始铁匠包图集和五阶木板采色，因此直接共用对应木种的运行时贴图。纸标签和深色装饰保留原色，没有额外生成重复的运行时 PNG。
- 三款盖板位置为原模型的固定造型，不添加开盖动画。原有盖板超出一格边界的部分保留。
- 体积形状按箱体和倾斜盖板预计算，倾斜部分以一像素单元、半像素对齐网格近似碰撞；渲染模型本身保持原坐标。初始化后四向形状缓存复用，不在 tick 或渲染循环中计算。
- 选中黑线通过 NeoForge 的 `ExtractBlockOutlineRenderStateEvent` 单独绘制烘焙模型边线，倾斜盖板不再显示阶梯轮廓；不改变碰撞和选中判定。边线在模型加载/资源重载时缓存，去除重复边、共面接缝和双面纸标签边，保留原版遮挡、线宽及高对比度模式。调试形状模式仍显示原始体积形状。

## 储物与制作

`AurorianStorageCrateBlock` 继承原版 `BarrelBlock`。前两款复用原版木桶方块实体，双层款使用继承木桶的 `DoubleStorageCrateBlockEntity`（`theaurorian2:double_storage_crate`），将库存扩为 54 格，复用原版六行 `ChestMenu`、存储与开关逻辑，并注册六面物品能力。没有新增容器菜单类型、ticker、方块实体渲染器、Mixin 或网络包。

支持原版三行/六行菜单、物品同步、漏斗及六面物品能力、比较器信号、改名、开关声音、库存和名称存档、打碎时掉落自身与全部库存。上方有完整方块也能打开，不合并容器。

界面默认标题使用独立翻译键 `container.theaurorian2.storage_crate`（中文“板条箱”，英文“Crate”）。菜单提供器仅替换显示名称，由底层容器创建对应行数的菜单并处理锁与战利品；自定义名称优先，原版木桶标题不受影响。

旧存档通过 `ChunkDataEvent.Load` 自动升级双层款：在实体延迟加载之前，仅将匹配双层方块的 `minecraft:barrel` 实体 ID 改为 `theaurorian2:double_storage_crate`。原有 0–26 格槽位、名称、锁、战利品表/种子、组件和附件保持原值，新增 27–53 格为空；方块/物品注册 ID 不变。只检查当前加载区块的数据，不查询其他区块或执行每 tick 扫描。

五块对应木板和三块对应半砖制作盖板款，摆法为 `PPP / P P / SSS`。物品放入工作台后按盖板款 → 斜盖款 → 双层款 → 盖板款循环转换，每次一比一。同原版木桶可作 300 tick 燃料。

## 验证

- 检查三份模型的几何、UV、旋转和展示参数与源 JSON 相同；十五份 Blockbench 模型保留源结构，嵌入贴图与运行时图集一致。
- 客户端资源加载和十五款实际摆放检查；逐一打开十五个菜单，确认前两款 27 格、双层款 54 格及同步物品数量。
- 选中轮廓：检查全部 180 个方块状态的缓存；客户端实拍三款造型的四个水平朝向、原轮廓对比和高对比度模式，并确认资源重载后缓存重新生成。碰撞实现未改动。
- 标题：中文客户端逐一打开十五款板条箱，确认实际菜单标题“板条箱”；客户端及专用服务器均验证自定义名称优先、原版木桶标题保留，默认标题不写入实体自定义名称。
- 专用服务器验证十五款四向放置、碰撞存在、原版方块实体合法性、六面物品能力、封顶后打开、开关状态、比较器、名称掉落和库存仅掉落一次。
- 十五款均完成实际上下漏斗传输；五个制作配方、十五个循环转换配方实际匹配。
- 保存并重启专用服务器，检查十五款容器的最后一格物品、数量、自定义名称、方块和实体类型，以及燃烧时长。
- 双层扩容：五种木材均检查 54 格菜单、最后一格同步及 Shift 快速取放；六面能力暴露 54 格，实际漏斗可向第 28 格插入并从第 54 格取出。
- 写入五种旧版 27 格木桶实体存档并重启，确认自动升级保留槽位 0/26、名称、自定义数据、未开启战利品表及种子；新实体的槽位 53 重启后保留，升级后再次重启正常。打碎时检查槽位 0/26/27/53 的物品各掉落一次及一个箱子自身。
- 正常构建后检查发布 JAR 不含临时验证代码。
