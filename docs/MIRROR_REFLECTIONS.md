# 长镜实时倒影

五种长镜共用同一实现，木材配色、物品和方块注册名、合成配方、两格高的挂墙方式不变。

## 游戏表现

- 从正面靠近镜子，可以看到自己、装备、身后的方块、生物、掉落物和动态箱子。
- 支持四个水平朝向；放置、拆除方块和光照变化后会自动更新缓存。
- 水和玻璃使用原版场景网格，透明面随倒影视点重新排序。
- 天空、日月星辰、云和雨雪使用独立的倒影视角，资源重载后重新取得当前资源包的数据。
- 只处理八格内、正面可见的镜子。默认最多两面同时更新；超出数量、距离或朝向范围时显示原静态镜面。
- 不递归渲染镜子中的镜子；镜中的其他镜子保留静态镜面。
- 新场景网格尚未准备好时保留静态镜面或上一幅完整倒影，避免短暂透过未加载的墙体看到天空。
- 离开镜子五秒后释放缓存和离屏目标。关闭功能、离开世界或重载资源也会释放并重建资源。

## 配置

首次启动后生成在游戏目录的 `config/theaurorian2-mirrors.toml` 中，只影响本机客户端。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 设为 `false` 恢复静态镜面 |
| `maxMirrors` | `2` | 同时更新的镜子数量，允许 1～4 |
| `resolution` | `256` | 倒影宽度，高度为两倍；允许 64～512 |
| `fps` | `30` | 倒影刷新上限，允许 5～60，不限制游戏本身帧率 |
| `sceneDistance` | `16` | 缓存的场景半径，允许 8～24 格 |

场景内最多绘制 48 个实体（包含本地玩家）和 64 个动态方块实体。整个场景缓存最多 256 个区段，只读取已加载区块，不请求服务器加载额外区块。远处场景会通过雾效淡出。

## 实现与兼容边界

`LongMirrorBlockEntity` 仅用于原版可见区段中的镜子发现，没有方块实体 ticker、额外的持久化内容或自定义数据包。两半都提供发现标记，渲染时按镜子底部坐标去重，覆盖跨区段的镜子。

旧存档中的镜子原先没有方块实体。区块加载事件先检查区段调色板，仅对包含长镜的区段补齐缺失标记；不改动已有方块 ID、朝向或配方。专用服务器不会加载倒影渲染类。

优先复用了 NeoForge 注册、区块加载事件、渲染状态提取事件、几何提交事件和原版渲染接口。三个客户端 Mixin 的原因和范围如下：

1. `MirrorSceneInvalidationMixin`：公开事件没有覆盖相机身后所有方块及光照引起的区段网格失效。在 `LevelRenderer.setSectionDirty` 入口只标记已有的镜面缓存脏区段，不取消原方法；`allChanged` 用于资源和渲染选项重置。
2. `MirrorRenderTargetMixin`：原版天空、云和天气直接取得输出目标，忽略通用输出覆盖。只在镜面渲染的 `try/finally` 范围内将颜色／深度视图路由到镜面目标，结束后恢复主视角的目标、投影、雾效和摄像机常量。
3. `MirrorCloudTextureAccessor`：读取已解码、不可变的资源包云纹理数据，给各镜面创建独立云网格；不在渲染中读文件，不修改主视角云网格。

场景快照在客户端线程按区段取得，单工作线程编译，一次只有一个待完成任务。GPU 上传、透明排序和绘制留在渲染线程。版本检查会丢弃构建期间又被修改、移出范围或已卸载的结果。区段编译采用当前 AO／树叶设置，并保留 NeoForge 附加区段几何回调。

如果渲染出现异常，本次会话回退为静态镜面并记录一次原因，可通过重载资源或重新进入世界恢复。没有对第三方光影、替代渲染器或自定义天空实现作全面兼容保证；普通粒子没有额外复制到倒影中。

## 验证记录（2026-09-08）

- 客户端实测五种木材 × 四朝向共 20 种组合，检查人物、其他实体和动态木箱的渲染状态及实际画面。
- 实测箱盖打开、方块／光照变化后的缓存重建、水／玻璃及侧向观察、雨天天空／云／天气渲染。
- 实测隔着玻璃仍能显示倒影，实体墙遮挡时停止更新；初次场景编译完成前不显示缺失墙面的倒影。
- 实测资源重载、两面镜子的同时渲染上限、背对镜子后的空闲资源清理、配置关闭再开启。
- 检查每次倒影提交后主画面的输出目标、摄像机常量、雾效和投影已恢复。
- 专用服务器验证五种长镜的 80 次放置／拆除组合、上下半边掉落、10 次支撑移除、无碰撞形状和配方标签。
- 用功能加入前保存的五种镜子验证加载时自动补齐标记，并在保存、重启后再次检查。
- 工作区 162 个改动 JSON 均可解析；Mixin JSON 压缩后原有语义保持一致，仅增加三个客户端钩子。
- 正常 `gradlew.bat build` 完成后检查发布 JAR 包含正式实现、不包含临时验证类。

测试日志中仍有此前已经存在的 `accessory_inventory` 存档附件反序列化报错，本功能没有修改该附件。

### 性能记录的适用范围

在本机 RTX 4060、1100×800、渲染距离 4、关闭垂直同步的简单室内场景下，正式渲染实现使用默认 30 FPS 倒影上限，做了两个固定视角开关阶段：

| 轮次 | 关闭：平均帧耗时 | 开启：平均帧耗时 |
| --- | --- | --- |
| 1 | 0.7068 ms | 0.7861 ms |
| 2 | 0.6093 ms | 0.6504 ms |

该测试在较长预热后执行，但轮次间仍有波动，不能外推为复杂基地或大量镜子的性能保证。以上采样完成于最后增加的“等待可见区段准备好再显示倒影”检查及玻璃遮挡修正之前；这两项随后单独完成客户端功能验证，没有把此前数值作为最终构建的精确性能承诺。

原人物倒影／固定房间原型保留在 `exports/mirror_reflection_trial/`，属于历史试验，不是正式实现。
