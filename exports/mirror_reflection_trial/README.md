# 长镜场景倒影试验

2026-09-08 的历史试验记录。五种长镜现已接入正式倒影实现，详见 [正式实现说明](../../docs/MIRROR_REFLECTIONS.md)。以下结果和限制仅描述当时的原型。

- `side.png`：斜视，透视和镜框裁切。

## 测试方法与结果

Minecraft 26.1.2，NeoForge 26.1.2.84，本机 NVIDIA GeForce RTX 4060。
客户端窗口画面 1100×800，渲染距离 4，关闭垂直同步、不限制主画面帧率。
单个北向长镜，256×512 反射纹理。倒影每个渲染帧更新，本次没有启用 30 FPS 倒影限频。
测试房间墙面、地板、窗户、工作台、熔炉及彩色羊毛使用实际世界中的方块模型；玩家使用原版人物、皮肤、姿态和装备渲染。

在预热之后交替执行关闭／开启／关闭／开启四个固定视角阶段，每个阶段取约 8 秒。屏蔽测试角色的键盘移动并固定位置和角度，使用 RenderFrameEvent.Post 间隔记录完整帧耗时。原始统计保存在 `benchmark.txt`，没有把 CPU 提交时间冒充 GPU 耗时。

| 轮次 | 关闭倒影：平均帧耗时 | 开启倒影：平均帧耗时 |
| --- | --- | --- |
| 1 | 1.0343 ms | 1.1148 ms |
| 2 | 1.0437 ms | 1.1446 ms |

两轮平均约 1.0390 ms → 1.1297 ms，增加约 0.091 ms；相当于此简单场景中帧率下降约 8%。开启阶段的第 95 百分位帧耗时约 1.89～1.91 ms。不能将此结果外推到复杂基地、大量镜子、低端显卡或光影模组。

四个区段首次编译约 12.817 ms，得到 9 个网格、157864 字节顶点和索引缓冲。这是一次性场景网格数据，不是整个功能的内存占用。首次编译未计入稳定阶段帧耗时，正式版需要异步或分帧处理以避免首次看到镜子时产生尖峰。

## 原型实现与限制

复用原版 SectionCompiler、方块／流体模型编译与人物渲染接口，使用独立离屏颜色／深度目标和镜像摄像机的非对称视锥；不递归调用主世界渲染，也不改动主视角的剔除结果。

这是固定位置的一面北向镜试验：场景缓存范围为 X/Z -16～15、Y 96～111，足以覆盖整个测试房间。不是完整的第二套世界渲染器，也不是可直接发布的家具功能。

尚未实现／验证：动态方块更新后缓存失效、移动光照刷新、镜子发现与多镜管理、全部朝向、区域外远景、完整天空和天气、其他实体与动态方块实体、透明物体随视点变化重排序，以及替代渲染器／光影兼容。原型调用了流体编译接口，但此轮截图场景未专门验证水面，不能据此宣称水和透明排序完全正确。

测试来源：`build/reflection-prototype-src/`，通过 `build/reflection-prototype.init.gradle` 临时加入编译；独立游戏目录为 `build/reflection-client/`。测试场景代码会自动布置、移动角色并退出客户端，只可用于该测试目录。

正式 `src/` 代码、资源和注册名没有因本次试验变化。正常 build 已重新运行，并检查最终 JAR 不含试验类。
